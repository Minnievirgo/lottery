## 4. F1 · 导出名单按抽签结果升序

### 4.1 排序规则（F1 与 F2 共用，必须抽为同一实现）

| 优先级 | 规则 |
|---|---|
| 1 | `result_name` 可解析为有限数字（`Number()` 且非 `NaN`）→ 按**数值升序**；`"5" < "13" < "38" < "43"` |
| 2 | 数值相同（非发言顺序场景中同一结果项可被多人抽中）→ 按 `drawn_at` 升序作为次级键 |
| 3 | 非数字文本（如「一等奖」）→ 排在**所有数字之后**，彼此按字典序（`localeCompare('zh-CN')`）稳定排列 |
| 4 | `null` / 空字符串 / 空白 → 排在最后，导出为空单元格且不报错 |
| 5 | 以上比较均不得改变行数据本身，仅改变顺序 |

> 默认假设 D1：非数字结果与空值仍参与排序与 F2 排程，不跳过、不过滤。

### 4.2 UI 交互

| 项 | 说明 |
|---|---|
| 入口 | 不变：名单弹窗 `#listModal` 底部「导出 CSV」按钮（`public/admin.html:97`、`public/admin.js:200`） |
| 视觉变化 | **无**（仅导出文件内容变化）；P1-1 若采纳，弹窗内表格行序同步调整 |
| 反馈 | 无新增提示；下载行为与文件名保持现状 |

### 5.2 时间参数表单字段与默认值

| # | 字段 | 控件 | 默认值建议 | 校验规则 |
|---|---|---|---|---|

| 2 | 上午开始时间 | `HH:mm` | `08:40` | 必填，合法 24 小时制；`00:00–23:59` |
| 3 | 上午结束时间 | `HH:mm` | `12:00` | 必须 > 上午开始 |
| 4 | 下午开始时间 | `HH:mm` | `14:00` | 必须 > 上午结束 |
| 5 | 下午结束时间 | `HH:mm` | `17:30` | 必须 > 下午开始 |
| 6 | 每人发言时长 | 整数（分钟） | `10` | 必须 **> 0**；`0`、负数、非数字 → 拦截 |
| 7 | 每人发言间隔 | 整数（分钟） | `5` | 必须 **≥ 0**（`0` = 无缝衔接，合法）；负数、非数字 → 拦截 |
| 8 | 启用课间休息 | 复选框 | **勾选**（默认假设 D4） | 取消勾选时禁用 #9 #10 |
| 9 | 每 N 人休息 | 整数（人） | `7` | 启用时：整数 ≥ 1 |
| 10 | 休息 M 分钟 | 整数（分钟） | `15` | 启用时：整数 ≥ 0 |
| 11 | 备注 | 多行文本 | `1、个人答辩时长每人13分钟，其中报告呈现10分钟，评委提问3分钟。` | 可清空 / 改写，≤ 200 字 |

> 示例规律复核：时长 10 分钟 + 间隔 5 分钟 = 步长 15 分钟 → `08:40–08:50`、`08:55–09:05`、`09:10–09:20` … 第 7 人 `10:10–10:20`；休息 15 分钟后第 8 人 `10:35` 开始。默认值即按此设定。
>
> 注意：默认备注写「每人 13 分钟」，与排程时长 10 分钟存在示例固有的不一致；本 PRD 原样保留示例文案且允许改写，见 §10-Q4。

### 5.3 边界规则

| 场景 | 处理 |
|---|---|
| 时间格式非法 / 上午开始 ≥ 上午结束 / 下午开始 ≥ 下午结束 / 下午开始 ≤ 上午结束 | 前端即时标红并**阻止导出**，逐条给出具体字段提示 |
| 每人发言时长 = 0 或负数 | 拦截并提示「每人发言时长必须大于 0 分钟」 |
| 每人发言间隔 < 0 | 拦截并提示「发言间隔不能为负数」；间隔 = 0 允许 |
| 课间休息 N < 1 或 M < 0 | 启用时拦截并提示对应字段 |
| 参与人数 = 0 | 「导出 CSV」「导出发言顺序」按钮禁用，或点击提示「暂无参与记录」 |
| 人数 > 上午 + 下午总容量 | 导出前预演算 → 弹窗 / toast 提示「当前时间参数最多可安排 X 人，当前 Y 人，超出 Z 人。建议缩短发言时长 / 间隔，或延长下午结束时间」，**不生成文件**（默认假设 D16，见 §10-Q10） |
| 上午时段排满 | 自动从下午开始时间继续排，插入「午休」跨列分隔行；序号连续不重置（用户已拍板） |
| 存在非数字 / 空结果 | 仍参与排程（按 §4.1 排在数字之后），不跳过、不报错 |
| 课间休息计数与上午→下午切换同时触发 | 优先插入午休行；课间休息的「已排人数」计数在下午段重新起算（默认假设 D17） |
| 备注为空 | 备注行仍生成，内容留空，不删行 |

### 5.4 排程算法（唯一实现，服务端执行）

1. 取该场 `participants`，按 **§4.1 同一排序函数**升序。
2. 步长 `S = 时长 D + 间隔 G`；首位开始 = 上午开始。
3. 第 `i` 位（`i>1`，无休息）：`开始 = 上一位结束 + G`；`结束 = 开始 + D`。
4. 若 `结束 > 上午结束` → 该位移入下午段：插入「午休」行，`开始` 重置为下午开始，`结束 = 开始 + D`；后续按 `S` 顺延。
5. 启用休息且已连续排满 `N` 位 → 插入「课间休息 M 分钟」跨列行，下一位 `开始 = 上一位结束 + M`（**覆盖**正常间隔 `G`，不叠加），以复现 `10:20 → 10:35`（默认假设 D5）。
6. 若 `结束 > 下午结束` → 计入超出人数，触发 §5.3 容量提示。
7. 序号 `1..N` 连续，跨上午 / 下午 / 休息行不重置。

## 6. F3 · 分享二维码

### 6.1 码内容规则

| 项 | 规则 |
|---|---|
| 内容 | `location.origin + '/?d=' + encodeURIComponent(drawId)`，与现有 `public/admin.js:179-183` 的 `copyLink()` **完全一致** |
| 禁止 | 硬编码任何域名（线上正式域名尚未确认）；不得写入 `localhost`、Render 临时域名常量 |
| 自适应 | 本地 `localhost`、Render 临时域名、最终正式域名均自动适配；`https` / `http` 自动沿用 |
| 短链 | 不使用 `/d/<id>` 作为码内容（其会 302 跳转，直达 `/?d=` 更稳；默认假设 D11） |
| 编码 | 标准 QR 矩阵，建议纠错等级 **H**（约 30% 容错）以容忍中心图案遮挡；UTF-8 字节模式；保留 ≥ 4 模块静区（quiet zone） |

### 6.2 视觉规格

| 项 | 规格 |
|---|---|
| 码点 | 标准 QR 网格模块矩阵，每个深色模块绘制为**实心圆点**（直径 ≈ 模块宽 0.8–0.9）；**不是**微信专有放射短线 |
| 外轮廓 | 圆形画布 / 圆形底色 + 圆形描边（小程序码观感）；QR 模块矩阵完整绘制在圆内接方形区域内，**不裁切任何模块** |
| 定位角 | 标准 QR 的三个方形 finder pattern **必须完整保留**；在其外圈叠加**同心圆装饰环**，视觉近似小程序码定位角。同心圆为装饰层，不替换 finder pattern |
| 中心图案 | 圆形星空 / 星系图，与 `public/cosmic-bg.js` 蓝紫金宇宙风一致：深蓝紫底 + 旋涡星云（`#5ad1ff` 青蓝 / `#c4b5fd` 紫 / `#ffd48c`、`#ffeeb9` 金）+ 白色星点 + 1–2 颗亮星 / 流星；**禁止猫爪或任何动物图案**；直径 ≤ 码面 20–22%，落在 H 级纠错可容忍遮挡范围内 |
| 输出 | Canvas 渲染，2x / 3x 分辨率 PNG（建议 ≥ 600×600 px），白色或透明底；文件名 `<title>-二维码.png` |
| 依赖 | 不新增 npm 依赖；QR 编码实现以单文件 vendor 源码随项目提交（不改 `package.json`），或由架构师选定等效零依赖方案（默认假设 D14） |

### 6.3 可扫性约束与冲突处理（**优先级声明**）

| 项 | 说明 |
|---|---|
| 冲突 | 诉求 A「视觉接近小程序码：同心圆定位角 + 圆形裁剪」 vs 诉求 B「必须能被微信 / 相机扫开直达抽签页」 |
| 处理原则 | **可扫性优先于视觉相似度**。装饰层不得改变、裁切或遮挡标准 QR 的定位图案与模块矩阵 |
| 默认假设 D12 | ① 同心圆 = 叠加装饰环，不替换 finder pattern；②「圆形裁剪」 = 圆形外框 / 底色，模块本身不裁切、四角不切 |
| 回退条件 | 若后续要求「真·同心圆替换定位角」或「裁切四角」，须先通过微信 + 系统相机真机扫码验证；不通过则回退本方案（见 §10-Q6） |
